# DeepDeck：从评测记录迭代工具接口

这是 2026-09-23 的历史案例，用来说明怎样提出假设和保留反例。数据不能充当当前价格或其他框架的默认基线。

## 原始证据

- [公开文章：通过 benchmark 迭代 Agent](https://deepdeck.getmegaportal.com/zh/blog/benchmark-driven-agent-iteration)
- [短引用版复测及逐次数据入口](https://github.com/jo32/DeepDeck/blob/a607ab5aab48500072b29506ec4a0580792bb9d7/docs/benchmarks/webmcp-reference-retest-2026-09-23.md)
- [直接工具版复测](https://github.com/jo32/DeepDeck/blob/5bc0e57ab46ef2544b6adf2663d3292019e88ac5/docs/benchmarks/webmcp-direct-retest-2026-09-23.md)
- [稳定声明与缓存复测](https://github.com/jo32/DeepDeck/blob/5bc0e57ab46ef2544b6adf2663d3292019e88ac5/docs/benchmarks/webmcp-cache-retest-2026-09-23.md)

每组是 MiMo V2.6 Flash 或 GPT-5.6 Luna，WebMCP ON 的六道高工具错误题。最初历史基线每题一次，后续各版本每题三次；六题都不是“原来一定失败”的任务。时间为 agentMs，不含环境启动、重置和评分；费用为 USD，Luna 为 API 等价估算。

## 第一轮：减少模型抄写身份信息

原接口让模型填写工具名以及 frameId、documentId、revision。trace 中 MiMo 会把工具清单 digest 当成具体工具 revision。业务工具选对也可能被拒绝，再发现再重试。

修改把定位身份放到宿主保存，工具清单返回短引用 toolRef，模型只选择引用和业务参数。执行前仍校验真实页面、区域和版本。它减少了身份填写机会，没有替模型选择正确业务工具，也没有解除过期校验。

以下为帮助理解的简化示例，不是某条真实订单日志或跨项目通用 API：

```json
{
  "discovery_result": {
    "tools": [{
      "name": "query_order",
      "toolRef": "w_a17",
      "inputSchema": {
        "type": "object",
        "properties": {
          "orderId": { "type": "string" },
          "email": { "type": "string" }
        },
        "required": ["orderId", "email"]
      }
    }]
  },
  "model_call": {
    "toolRef": "w_a17",
    "input": { "orderId": "ORD-123", "email": "buyer@example.com" }
  }
}
```

`w_a17` 来自程序生成的 discovery result，模型从清单取用。宿主把它映射回注册记录；导航/版本变化时拒绝失效引用并重新发现，不能把旧调用偷偷改绑到新页面。另一种实现可把注册信息藏在对象句柄中，或把业务函数直接注册给模型；这些是待比较的接口选项。

第一轮 MiMo 工具错误比例从 75.0% 降到 27.5%，六题耗时从 20.04 分钟到 5.75 分钟，轮次从 108 到 60.3。Luna 错误比例从 38.9% 到 21.6%，耗时从 3.07 到 3.02 分钟。历史任务最终都通过，因此不能把这些变化写成任务成功率提升。

另一个改动区分未执行与结果未知：若请求已经发出而回执丢失，应查业务状态再决定是否重试。查询失效工具和重复创建订单不是同一种错误恢复问题。

## 第二、三轮：步骤减少可能更贵，便宜也可能退步

下表费用、耗时、轮次折算为六题各运行一次的均值之和；成功数是全部 18 次尝试。不能将平均套题费用当成全部实验账单。

| 模型 | 版本 | 通过 | 轮次 | 分钟 | USD / 六题 | 加权缓存命中 |
|---|---|---:|---:|---:|---:|---:|
| MiMo | 短引用 | 18/18 | 60.3 | 5.75 | 0.026331 | 90.5% |
| MiMo | 直接业务工具 | 18/18 | 34.7 | 3.24 | 0.027850 | 68.8% |
| MiMo | 稳定工具声明 | 17/18 | 34.3 | 5.39 | 0.020288 | 79.0% |
| Luna | 短引用 | 18/18 | 41.7 | 3.02 | 0.036244 | 76.1% |
| Luna | 直接业务工具 | 18/18 | 32.7 | 2.22 | 0.042609 | 53.7% |
| Luna | 稳定工具声明 | 18/18 | 24.7 | 1.52 | 0.030326 | 54.5% |

直接注册业务工具省了步骤，缓存却下降，MiMo 和 Luna 平均费用分别上涨约 5.8% 和 17.6%。工具声明中不断变化的会话/页面身份是可修复的缓存破坏来源；总耗时和总账单还受其他运行因素影响。

下一轮把稳定名称/schema 与动态执行身份分开。步骤开始时冻结执行绑定，导航撤销绑定，读取预览不改变待执行请求的目标。稳定声明跨加载保留，当前可用状态另行提供；真正出现新能力时仍会产生缓存冷启动。

Luna 费用与耗时下降且 18/18 通过。MiMo 费用下降但一次工具调用名称/ID 异常导致 API 400，只有 17/18 通过；订单题也明显变慢。它不能被描述成相同质量下全面省钱提速。费用下降并不要求缓存比例大涨：Luna 少了后续重复输入，费用下降而命中比例仅从 53.7% 到 54.5%。

## 这些结果支持的结论范围

- 修复的是特定接口负担和状态管理，不证明某模型总体工具能力更弱或更强。调用次数更多不代表工具利用更有效。
- 六道选出的题、历史非同期对照、初始一次而后续三次，只支持局部探索结果。MiMo 原有一个极慢订单运行，不能以单个异常主导泛化结论。
- 短引用历史版还带两个未调用的 Jev 工具，后续不含；没有调用的工具也可能改变输入和缓存，属于配置差异。
- 正式失败和逐题退步保留；校准、评分凭证过期、环境启动中断分别记账。排除某题的补充分析不能替代包含它的主表。
- 该报告中的 input_tokens 已经不含 cached_input_tokens，不能再减一次。单价是历史冻结值，新的实验需要按实际 provider 语义及价格重建费用。
- 这组改动落在 DeepDeck 的 Browser/Cordis 插件，遵循该仓库上游 Harness 只读的约束；别的框架应使用其自己的扩展点。

可迁移的经验是：trace 定位错误机会 → 改变接口分工 → 保留状态校验 → 用相同业务结果验证 → 同时检查缓存账单和退步。不是“所有 Agent 都应该用 toolRef”或“直接函数一定更好”。
