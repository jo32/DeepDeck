# MiMo V2.6 Flash 与 Luna：DeepDeck Bench 对照

完成 49 题 × WebMCP ON/OFF，共 98 次尝试。MiMo 原始评分 ON 49/49，OFF 46/49；OFF 3 次超时。Luna 原始评分两组都是 49/49，但存在已记录的未完整执行题。

在 MiMo 与 Luna 共同完成、用量完整且排除已知未完整或未验证步骤的 45 题上，MiMo 两组合计耗时比 Luna 增加 48.2%，token 增加 102.8%。这是各一次实测，不能视为稳定模型排名。

| 模型 | ON / OFF 执行分钟 | 两组合计分钟 | 两组合计 token |
|---|---:|---:|---:|
| GPT-5.6 Luna | 25.5 / 37.5 | 63.0 | 11,585,104 |
| MiMo V2.6 Flash | 41.5 / 51.9 | 93.4 | 23,499,486 |

MiMo 自身 46 道有效成对任务：开启 WebMCP 后，耗时变化 -23.2%，token 变化 -15.5%。

主要核对结果：

- **md-8 OFF**：600 秒超时；第 25/26 步网络结果确认 /gb/products/t-shirt 返回 HTTP 500 / Internal Server Error，随后多次复现。模型转为读取 Docker 日志和依赖目录后等待恢复，未完成结账。原始失败保留，不能单独归因为模型能力。
- **ea-7 ON**：第 8 步 cancel_appointment 工具返回 ok:true、status:appointment_cancelled，确认从日程移除；取消原因为 schedule conflict。
- **ea-7 OFF**：第 21 步浏览器快照明确显示 Appointment Cancelled / Your appointment has been successfully cancelled；第 23 步重新打开 booking/reschedule/<reference>，显示 Appointment Not Found、记录已不存在。与 Luna 该题未完成取消不同，本轮 MiMo 完成了两步。
- **id-8 ON**：通过 get_financial_summary(period:month) 获得当月 invoiced=250 并查看发票列表；也尝试 /dashboard，但未证实成功打开题目要求的财务汇总页面。原始通过保留，严格完整任务效率对照排除本题。
- **id-8 OFF**：600 秒超时，未提交最终答复；多次浏览发票列表看到 $250.00，但未完成当月汇总要求。usageComplete=false，已记录部分用量保留，完整 token 总量置 null。
- **hev-9 ON**：注册免费票后，第 18 步调用 get_order_status，明确传入 o_ 订单号与 riley.fox@example.com，返回 COMPLETED / NO_PAYMENT_REQUIRED，完成订单查询。总耗时约 590 秒，接近 600 秒上限。
- **hev-9 OFF**：600 秒超时，无最终答复，84 次工具调用；未完成订单号和邮箱的查询，后期转向检查页面全局对象和 Harness WebMCP 配置。usageComplete=false，完整 token 总量记 null。

未对所有通过题逐步人工复核。保留原始判分，不把少量重点核对称为全量严格成功率。财务汇总 OFF 和订单查询 OFF 的完整用量缺失，因此不报告 MiMo OFF 全量 token 总数；部分已记录用量仍保留在原始数据中。

配置：小米官方接口、mimo-v2.6-flash、默认开启思考。正式首题已验证收到 assistant reasoning 内容。最初关闭思考的接入校准试跑单独存档并排除。日常配置未修改；站点已全部停止，临时密钥与配置副本已删除，生成文件中未检出本次 key。
