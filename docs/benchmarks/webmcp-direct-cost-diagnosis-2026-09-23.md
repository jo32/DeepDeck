# WebMCP 直接调用版：费用诊断

本次只分析已完成的原始运行与当前实现，没有修改待测 runtime，没有新增收费调用。对照为每题 3 次的短引用版与直接调用版，费用均为冻结的 USD 单价估算，含实际缓存读取。

## 账单事实

原价输入与缓存输入不同价：MiMo 为 $0.14 / $0.0028 每百万 token，前者是后者的 50 倍；Luna 本报告按 $0.20 / $0.02 估算，差 10 倍。减少总 token 不代表减少原价 token。

| 模型 / 用例 | 轮次：短引用 → 直接 | 原价输入 token：短引用 → 直接 | 缓存命中率：短引用 → 直接 | USD：短引用 → 直接 |
|---|---:|---:|---:|---:|
| mimo / react-auth-boundary | 26.7 → 11.3 | 43,065 → 63,961 | 94.5% → 70.8% | $0.009900 → $0.009952 |
| mimo / lh-7 | 9.7 → 7.7 | 23,979 → 42,478 | 89.0% → 66.2% | $0.004161 → $0.006417 |
| luna / directory-filter | 4.0 → 5.0 | 12,408 → 29,076 | 71.6% → 49.0% | $0.003383 → $0.006659 |
| mimo / ea-5 | 3.7 → 2.0 | 18,161 → 10,911 | 74.6% → 63.1% | $0.002767 → $0.001608 |

以上为 3 次均值。课程题 MiMo 总输入约 218,709 → 125,700 token，但原价输入约 23,979 → 42,478，费用上升 54.2%。预约题缓存命中率也下降，但原价输入同时下降，费用下降 41.9%。验收应看总费用与完成质量，不能只看命中率。

## 请求轨迹与代码证据

MiMo lh-7 第 1 次：短引用版 10 次模型回复只有 1 版工具清单；直接版 6 次回复出现 5 版工具清单。

| 直接版回复轮次 | 工具清单版本 | 未缓存输入 | 缓存输入 |
|---:|---:|---:|---:|
| 1 | 1 | 9,893 | 4,096 |
| 2 | 2 | 6,176 | 8,192 |
| 3 | 3 | 7,696 | 8,192 |
| 4 | 4（加载中，WebMCP 清单为空） | 7,175 | 8,192 |
| 5 | 5 | 9,700 | 8,192 |
| 6 | 5（清单未变） | 888 | 17,856 |

报名工具名尾部依次为 _4 → _6 → _b → 消失 → _g。`WebMCPBindings` 使用每会话随机前缀和递增编号；绑定指纹含 tab/document/tool 完整对象。文档、注册状态或 schema 变化后，名称可能更新；加载中 discover 返回空集合，runtime 会删除注册，加载完成再生成新名称。请求因此改动顶层 tools。名称变化同时影响复用和旧名称调用错误。

这不是全部原因的因果证明：Luna directory-filter 第 1 次，清单没变，第 2 次回复仍有 11,278 未缓存输入，而短引用版对应轮次只有 1,334 未缓存 / 9,728 缓存。服务端缓存存储与路由、请求其他部分变化也要核验；现有日志不足以证明这一次未命中的唯一原因。更短的任务也会少掉后半段容易命中的轮次，从而降低合计命中比例。

## 降费方案与验收

1. 优先减少不必要的工具清单变动：模型看到的能力名与业务参数尽量稳定；页面、frame、document、revision 等执行绑定由宿主保存。不能直接删除随机后缀后，把旧调用悄悄转到新页面。应冻结每次模型请求的绑定，执行前核对；刷新只更新下一请求的绑定。不同业务 schema 与语义不同的同名工具仍须区分。
2. 加载中的空清单不应立即造成整套工具反复删除和重建。可评估在加载完成后再组装下一次请求，或保留稳定声明并在宿主暂禁执行；均须设置等待上限并验证未知页面不能执行旧操作。
3. 稳定工具排序、描述和参数序列化。工具描述中的页面状态、订单引用等动态信息应与固定业务说明分离；不要擅自删除网站提供的业务约束。不能为了缓存长期保留所有失效工具而无限增加清单。
4. 减少重复材料：直接工具已声明业务 schema 时，browser_context 默认返回必要状态和工具变化，详细 schema 按需读取。builder 专属说明留在 builder 模式。稳定规则放在前面，动态状态追加在后面；接口实际支持的缓存选项需分别核对，不能把 OpenAI Responses 专有能力直接套给 MiMo。
5. 将“同等完成质量下的 USD 总费用”作为发布验收条件。在相同配置、工具集合下交错运行旧/新版本，各题重复，并把首次请求与后续复用分别统计；保留失败、重试、预热费用，不能为了提高命中率额外空跑或排除不利结果。小样本不过关不切默认实现，通过后再扩至完整题集。

在本次直接版总输入与输出量完全不变的假设下，MiMo 缓存命中从 68.8% 恢复到约 70.7%、Luna 从 53.7% 恢复到约 62.7%，美元估算即可与短引用版持平。超过门槛才更便宜。这是算术门槛，改实现会改变轮次与 token，不能作为承诺。

无法保证任意一次任务都更便宜：模型行为及服务端缓存不完全受客户端控制。可保证的是采用明确的费用回归门槛；若必须保证绝对不超某个金额，需保守计价的请求前预算限制与输出上限，但可能提前停止，无法同时保证任务完成。
