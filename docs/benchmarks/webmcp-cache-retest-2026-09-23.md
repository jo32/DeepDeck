# WebMCP 缓存恢复复测（2026-09-23）

## 改动

工具名按业务名称、描述和参数的规范化内容生成，去掉随机会话/页面编号。宿主保留独立的 tab/document/frame/revision 校验。每个模型步骤先冻结执行绑定；读取页面状态或预览提示不能把旧请求改绑到新页面。导航立即撤销执行绑定。

工具声明跨页面加载、导航保留，避免顶层工具列表反复清空。新业务 schema 仍增加声明；累积声明超过 128 项时清理历史项，不裁剪更大的当前可用清单。当前可用名称通过 Cordis 动态 context 追加到对话，固定说明不改写。全部实现位于 Browser 插件，未修改上游 Harness 源码。

## 口径

6 题 × 每题 3 次 × MiMo/Luna，共 36 次正式尝试，WebMCP ON。模型路由、输出上限、上下文窗口与历史参数逐条核验。每次重置网站，使用新的浏览器与 Harness 会话；保留所有正式尝试。时间仅为 agentMs，不含环境启动、重置、评分。美元费用按实际未缓存输入、缓存输入、缓存写入和输出分别计算；Luna 是 API 等价估算。

对照是历史结果，不是同一时段的随机 A/B。短引用历史版带两个未调用的 Jev 工具；首次直接调用版与本次均不含它们。服务端负载、缓存与模型波动不可完全控制。缓存命中率为所有输入的加权合计，不是逐题百分比平均，也没有额外空跑制造命中。

两次最初环境启动因本地构建产物缺失被中止，发生在 running-agent 之前，没有记录到模型请求/用量；完整记录保存在 startup-aborted。修复后两组从头开始，本次正式尝试不择优替换。

## 如何读这次结果

这次修复了可控的缓存破坏：同一业务工具的名称、描述、参数内容和已有声明保持稳定，页面身份放在宿主内校验。它没有保证所有请求都能命中服务端缓存。

- mimo：缓存 68.8% → 79.0%；全部正式尝试总费用 $0.083550 → $0.060864（下降 27.2%）；通过 17/18。
  失败会提前结束，不能把总费用下降直接当作同等完成质量的节省。排除整个失败题目，仅看其余 5 题、各 3 次全部成功：每组 $0.026222 → $0.018658（下降 28.8%）。正式总表仍保留失败题全部 3 次。
- luna：缓存 53.7% → 54.5%；全部正式尝试总费用 $0.127827 → $0.090977（下降 28.8%）；通过 18/18。

MiMo 的 hev-1 第 3 次失败：实际返回的 assistant 工具调用块里含空名称和空 ID，后续请求被接口以 `messages[4].tool_calls[1] is missing a function name`、HTTP 400 拒绝。已经拿到场地查询结果，但没有正常完成回答，按失败计；没有重新跑一次覆盖它。这里未修复模型/适配器的异常调用格式处理。

## 用具体例子解释

- 登录题：以前“同一个查询工具”会随页面编号变成新工具，模型的工具清单不断变化。本次同题 3 次的初始声明完全一致。MiMo 三次合计的 request/header 记录由 17 次减少到 3 次，Luna 由 6 次减少到 3 次；这些是声明记录数，并非模型请求总数。
- Luna 课程题：一次运行前两轮分别有 10,490 和 11,276 个未缓存输入 token。登录后工具数从 57 增到 59，新增能力仍改变清单。接下来的 4 轮分别命中 10,752、10,752、10,752、12,800 个 token。页码不再导致改名，但真正新增的工具仍有冷启动成本。
- Luna 课程题平均费用 $0.013217 → $0.006556，耗时 35.0 → 16.1 秒，轮次 8.7 → 4.7。少了很多后续轮次，也就少了很多“本可命中缓存的重复输入”；因此花钱少了，并不自动意味着缓存百分比明显变高。
- 并非每题都更便宜：Luna 的 hev-1 平均 $0.002666 → $0.003604，MiMo 的 directory-filter 平均 $0.002156 → $0.002731。逐题表保留这些退步。

MiMo 订单题三次都完成，但平均耗时 41.7 → 177.1 秒，拖慢整组（194.3 → 323.3 秒）。本次没有证据证明等待变慢完全由 Harness 或完全由服务端造成，不把费用下降写成提速。

## 仍未恢复的部分与下一步

Luna 总命中率仍明显低于短引用版的 76.1%；MiMo 也应与短引用版 90.5% 对照。不能把本次描述为缓存全面恢复。

当前业务工具来自正在打开的页面。站点如果能从一开始声明完整、稳定的工具 schema，并把“此刻是否可调用”单独报告，登录和跳转就不必再改顶层清单；这是下一步最值得验证的方向。对于只能逐页发现工具的站点，需要单独对比固定执行入口方案，不能靠预先偷看测试题、无意义预热或增加轮次提高命中百分比。此项尚未实现或测量。

验收同时看任务是否完成、原价输入数量、真实总费用及缓存命中率；不以单一百分比代替成本与质量。
