# WebMCP 直接调用版复测（2026-09-23）

选取之前工具调用错误较多的 6 道题，MiMo V2.6 Flash 与 GPT-5.6 Luna 各跑 3 次，共 36 次正式尝试；WebMCP 均为 ON。原版与短引用版使用已经保留的历史结果。原版这 6 题最终都通过，因此本次主要检验错误、步骤、时间和费用，不把工具错误减少描述为任务通过率提升。

## 判断

相较上一版短引用实现，两组的任务通过率均保持 18/18，轮次和总体耗时下降，但工具错误率、费用没有继续改善。

- MiMo：6 题平均耗时下降 43.7%，轮次下降 42.5%；费用上升 5.8%。WebMCP 错误从 14/51（27.5%）升至 17/56（30.4%）。
- Luna：6 题平均耗时下降 26.7%，轮次下降 21.6%；费用上升 17.6%。WebMCP 错误从 8/37（21.6%）升至 10/42（23.8%）。
- MiMo 的课程题是明显退步项：3 次运行的 WebMCP 错误从 3 次增至 9 次，平均耗时约 40 秒持平，平均费用从 $0.004161 升至 $0.006417。Luna 的目录筛选平均从 18.2 秒增至 21.1 秒，费用也上升。
- 新版仍有页面切换、工具重新注册后的失效调用。MiMo 出现 5 次 unknown tool、9 次 stale_webmcp_tool；Luna 出现 7 次 stale_webmcp_tool。其余两组各 3 次为执行期间页面路由变化。这些错误都保留在统计中。
- MiMo 有 4 次调用用了最新请求工具列表里已经不存在的名字；另 1 次 unknown tool 发生在同轮操作改变注册状态之后。Luna 没有沿用已从最新列表移除的名字，但会在请求生成后页面继续变化时遭遇失效。
- 输入缓存命中率：MiMo 90.5% → 68.8%，Luna 76.1% → 53.7%。总输入和输出 token 均下降，但较贵的未缓存输入增加，抵消了节省。动态工具名称、业务 schema 和历史 Jev 工具描述差异都可能改变缓存前缀；跨时间测试不能单独证明哪一个因素导致下降。

判断：直接注册工具减少了步骤，值得继续，但当前实现还不是全面胜过短引用版。下一步应改善工具身份的稳定性、页面变化后的刷新与错误恢复，再复测；不应通过放宽跨页面校验来压低错误数。

课程和订单的 12 次重点检查全部取得工具返回证据：课程题完成登录、报名并进入目标课程；订单题成功创建，再查询得到相同订单引用与 COMPLETED 状态。36 次用量记录完整，美元估算总费用为 $0.211377；这是两模型所有 36 次尝试的合计。

## 运行口径

- 题目：react-auth-boundary、directory-filter、ea-5、lh-7、hev-1、hev-9。每次重置站点并新建浏览器配置和 Harness 会话。
- 请求中的模型、上下文窗口、输出上限和适配器默认值逐条与原版核对；未额外设置思考强度或步骤限制。工具注册形式是本次待测变量。旧版还注册了 jev_browser_run、jev_evaluate，当前 main 已移除；这两者在原版和短引用版所选 6 题均未被调用，但其描述可能影响输入 token 和模型行为。除此之外的工具名称集合相同。
- 直接调用版所有尝试均保留，包含任务失败、超时和工具错误；本次没有择优重跑。
- 时间为 agentMs，排除环境启动、重置和评分。步骤为 Harness 执行轮次，不是鼠标点击数。表中时间、步骤和费用均折算为完成同一组 6 题一次的均值；WebMCP 错误数则展示各版全部尝试的合计及比例。
- 这是跨时间的选题回归，不是完整 43 题、WebMCP OFF 对照或同期随机 A/B。服务负载、网络、缓存状态均可能影响耗时及费用；结果不能全部归因于代码修改。

## 缓存和费用

费用沿用上一份已发布报告冻结的美元单价，不重新换汇；Luna 为 API 等价估算，不是订阅账单。

| 模型 | 未缓存输入 / 百万 token | 缓存读取 / 百万 token | 输出 / 百万 token | 缓存写入 |
|---|---:|---:|---:|---:|
| MiMo | $0.14 | $0.0028 | $0.28 | 未定价，实际使用为 0 |
| Luna | $0.20 | $0.02 | $1.20 | $0.25 / 百万 token |

`总费用 = (未缓存输入 × 对应单价 + 缓存读取 × 对应单价 + 缓存写入 × 对应单价 + 输出 × 对应单价) / 1,000,000`。记录中的 input_tokens 已是未缓存输入，不再次减去 cached_input_tokens。缓存命中率 = cached_input_tokens / (input_tokens + cached_input_tokens)。缺失使用量不当作零费用。

| 模型（直接版，18 次合计） | 未缓存输入 | 缓存输入 | 缓存写入 | 输出 | 合计 USD | 用量完整 |
|---|---:|---:|---:|---:|---:|---|
| mimo | 546402 | 1204416 | 0 | 13149 | $0.083550 | True |
| luna | 546849 | 634368 | 0 | 4808 | $0.127827 | True |

重复执行可能提高服务端缓存命中；每次新建浏览器并不会清空服务端缓存。新增直接工具的名称和业务参数 schema 也会改变请求内容，因此费用变化应结合实际 token 和缓存数据解释。
